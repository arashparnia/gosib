# Getting help

Use [GitHub Discussions](https://github.com/arashparnia/pechpech/discussions) for integration questions and design discussions. Use the [issue forms](https://github.com/arashparnia/pechpech/issues/new/choose) for reproducible bugs and feature proposals. Check existing reports first and include the exact package version or commit, OS/toolchain and a small synthetic reproduction.

Start with the [integration guide](docs/integration.md), [wire specification](docs/protocol.md) and [qualification limits](docs/qualification.md). A route failure, OS permission failure, local queue admission, relay storage acknowledgment, endpoint receipt and application result are different observations; say which one you are reporting.

Do not attach private keys, operational databases, customer data, unredacted device identifiers or credentials. Use [private vulnerability reporting](SECURITY.md) for security issues and the [code of conduct](CODE_OF_CONDUCT.md) for conduct concerns.

Support is provided on a best-effort basis. Support, compatibility and security-response deadlines are not contractual commitments. Physical networking claims need evidence from the intended devices and host application.
